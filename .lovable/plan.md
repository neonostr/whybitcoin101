# Fix broken shared video links

Right now a shared link like `/video/bitcoin-timing-early-or-late` only works for people whose own browser already stored that video. Everyone else gets bounced to the homepage — so links shared on social media show nothing.

## What changes

1. Add one shared list of the six videos (slug, title, description, link) that the site reads from.
2. The resources section uses that list, so nothing about the page's look or content changes.
3. The video page looks the video up by its address instead of browser storage, so the video opens for every visitor, first time, no redirect.
4. If a link points at a video that no longer exists, the visitor lands on the homepage as before.
5. The six static preview pages under `/video/...` keep their existing titles and social preview tags; they hand the visitor straight to the matching video page instead of stashing data in browser storage.

## Technical notes

- New `src/data/videos.ts` exports a typed array with `slug`, `title`, `description`, `type`, `url`; slug generated by the same rule `VideoModal.createSlug` uses today.
- `Resources.tsx` imports the array instead of its local `videos` const.
- `VideoPage.tsx` resolves `slug` from that array; `navigate('/', { replace: true })` only when unknown.
- `public/video/<slug>/index.html` redirect targets `/video/<slug>`; `scripts/generate-sitemap.ts` keeps working off the same folder listing.
- No change to `VideoModal` share behaviour on the main site beyond dropping the now-unneeded localStorage write.
